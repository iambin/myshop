新手小白也能懂：網站備份與還原教學

你好！這份教學是專門為第一次接觸網站管理的朋友，以及容易看字跳行或眼花的朋友設計的。

我們不用複雜的黑話，也不用背難記的公式。跟著一步一步做，你也能隨時保護你的網站資料，遇到任何突發狀況都能在 3 分鐘內復原！

★ 30 秒先看結論：備份到底在備份什麼？

把你的網站想像成一間實體雜貨店：

  • 不需要天天備份的：店面設計圖（程式碼）。
    只要你的程式碼有存在 GitHub / 雲端倉庫，就不用擔心，隨時可以重新蓋好。
  • 真正必須定時備份的：網站「三寶」。
    如果這三樣東西丟了，商品和客人的紀錄就真的找不回來了！

第一章：必須備份的「網站三寶」是哪三樣？

第一寶：商品帳本

1. SQLite 資料庫檔案

檔案位置：server/data/shop.db

白話說明：這是店裡的「進銷存總帳本」。裡面記著：有哪些商品、商品多少錢、分成哪些類別、還有多少客人來逛過。如果帳本沒了，店就等於要重新開張。

第二寶：實體相簿

2. 上傳的商品圖片目錄

檔案位置：server/data/uploads/

白話說明：這是你上架商品時拍的「照片櫃」。帳本裡雖然記錄了商品名稱，但實體照片都存放在這個資料夾裡。沒備份的話，所有商品圖片都會變成破圖裂掉。

第三寶：店面密碼鑰匙

3. 秘密設定檔 (.env)

檔案位置：server/.env

白話說明：這是進後台的「通行證密碼」與安全防偽暗號。裡面寫著管理員密碼和保護金鑰。

安心提醒：不用備份的部分

React 與 Express 程式碼

位置：client/ 與 server/src/

白話說明：這些就像雜貨店的「鋼筋與水泥」，平常寫程式只要有用 Git 存到 GitHub，全世界都有副本，不用花空間每天備份。

第二章：如何備份？（超簡單兩步驟）

請根據你的使用環境，選擇「方式 A（本機電腦）」或「方式 B（雲端 VPS 伺服器）」：

A
方式 A：我在自己的 Windows / Mac 電腦上開發

最直覺、用滑鼠點點複製貼上就能搞定！

動作 1 關閉正在運行的終端機（Ctrl + C）：確保資料庫沒有正在寫入資料。

動作 2 找到資料夾並複製：

  1. 打開專案中的 server 資料夾。
  2. 找到名為 data 的資料夾（裡面裝有 shop.db 和 uploads 照片）。
  3. 按滑鼠右鍵點 複製。
  4. 在桌面或外接硬碟建立一個名為 myshop_備份_日期 的資料夾，按右鍵 貼上。
  5. 別忘了把 server/.env（如果有的話）也複製過去放一起！

恭喜你！這樣就備份完成了，就是這麼純樸簡單！

B
方式 B：雲端伺服器 (Linux / VPS) 一鍵備份

直接複製底下指令，貼進終端機按 Enter 就完成！

🚨 如果終端機出現「command not found: sqlite3」怎麼辦？

這代表你的伺服器（或 Mac）剛買來，還沒安裝 sqlite3 命令列工具。你有以下兩種超簡單解法（選其中一種即可）：

  • 解法 1（花 5 秒安裝工具）： 複製下方安裝指令貼上並按 Enter： 
    # Ubuntu / Debian 伺服器：
sudo apt update && sudo apt install -y sqlite3

# Mac 電腦 (若使用 Homebrew)：
brew install sqlite
  • 解法 2（免裝任何工具！停機 3 秒直接打包法）： 如果不想安裝工具，先讓伺服器暫停 3 秒，直接整包打包，完全不受 WAL 模式影響： 
    # 1. 建立備份資料夾
mkdir -p ~/backups

# 2. 暫停伺服器（確保資料不寫入）
pm2 stop myshop-server 2>/dev/null || true

# 3. 直接打包整個 data 目錄與設定檔
cd ~/myshop/server
tar -czvf ~/backups/myshop_backup_$(date +%Y%m%d_%H%M%S).tar.gz data .env 2>/dev/null || true

# 4. 重新啟動伺服器
pm2 start myshop-server 2>/dev/null || true

# 5. 查看備份成果
ls -lh ~/backups

標準熱備份法（已安裝 sqlite3 時）：
系統專屬的 .backup 功能就像按相機快門一樣，在伺服器不停機的狀態下，拍出最乾淨無損的資料庫快照：

請複製以下整段指令（點擊右上角藍色按鈕）：

# 步驟 1：建立放備份的保險箱目錄
mkdir -p ~/backups

# 步驟 2：拍下資料庫快照，並把照片和資料打包成壓縮檔
cd ~/myshop/server
sqlite3 data/shop.db ".backup 'data/shop_temp.db'"
tar -czvf ~/backups/myshop_backup_$(date +%Y%m%d_%H%M%S).tar.gz \
  data/shop_temp.db \
  data/uploads \
  .env 2>/dev/null || true
rm -f data/shop_temp.db

# 步驟 3：查看打包好的檔案（確認檔案大小不是 0）
ls -lh ~/backups
🐳 如果你是用 Docker Compose 部署的？點此展開專屬指令

如果你的專案是在 Docker 容器中跑，宿主機本身不用安裝 sqlite3，可以直接透過 Docker 臨時容器進行備份：

mkdir -p ~/backups
docker run --rm \
  -v myshop_server-data:/data:ro \
  -v ~/backups:/backup \
  alpine sh -c '
    apk add --no-cache sqlite &&
    sqlite3 /data/shop.db ".backup /backup/shop.db.bak" &&
    tar -czf /backup/myshop_docker_$(date +%Y%m%d_%H%M%S).tar.gz /backup/shop.db.bak /data/uploads/ &&
    rm -f /backup/shop.db.bak'

💡 打包完成後會看到什麼？

在 ~/backups 目錄下，會出現一個類似 myshop_backup_20261011_120000.tar.gz 的壓縮包。這個小檔案就是你的全部心血，妥善保管它！

第三章：網站壞掉了！如何用備份檔快速還原？

如果哪天網站商品被不小心刪光了，或者伺服器當機資料毀損，請放輕鬆，拿出你的備份檔案，照著「黃金三步法」來復原：

🛑 第一步：先停止運行網站（讓系統暫停寫入）
⬇️
📦 第二步：把備份檔案放回正確目錄（覆蓋損壞的舊檔）
⬇️
🚀 第三步：重新啟動網站並在瀏覽器檢查商品
1 詳細還原步驟教學（伺服器操作）

步驟 1.1：先停止網站伺服器

如果是使用 pm2 或 systemd 管理，先暫停它（避免在換資料庫時還有客人下單）：

# 若使用 pm2：
pm2 stop myshop-server

# 若使用 Docker Compose：
docker compose down

步驟 1.2：把備份檔案解壓縮還原

請將 檔名 換成你當初備份出來的真實檔名（例如 myshop_backup_20261011.tar.gz）：

# 切換到後端目錄
cd ~/myshop/server

# 解壓縮備份檔案到目前目錄
tar -xzvf ~/backups/你的備份檔案名稱.tar.gz

# 如果備份檔裡有名為 shop_temp.db 的快照檔，將其轉正為 shop.db
[ -f data/shop_temp.db ] && mv -f data/shop_temp.db data/shop.db || true

# 刪除舊的臨時暫存快取（重要！避免新舊資料衝突）
rm -f data/shop.db-wal data/shop.db-shm

步驟 1.3：重新啟動網站並打開網頁

# 若使用 pm2：
pm2 start myshop-server

# 若使用 Docker Compose：
docker compose up -d

# 檢查後端是否正常在 port 3001 呼吸（回傳 200 即代表健康）
curl -I http://localhost:3001/api/health

第四章：新手常見的四大翻車陷阱

陷阱 1：終端機出現「command not found: sqlite3」

原因：這代表主機作業系統（Ubuntu / Debian / Mac）沒有內建 SQLite 的命令行工具。
最快解法 A：只要跑這行就能裝好：sudo apt update && sudo apt install -y sqlite3
無腦解法 B（免裝工具）：直接採用「方式 B 解法 2」，先 pm2 stop myshop-server 停止 3 秒，直接整包 tar 打包，完全不需要任何額外軟體！

陷阱 2：千萬不要在網站跑動中，只複製單一個 shop.db

為什麼？
SQLite 有一個「幫手記錄本」叫做 shop.db-wal。很多最新的修改其實暫時寫在這個幫手本子裡。如果你只複製了 shop.db，最新的商品可能會漏掉！
正確做法：一定要用 sqlite3 shop.db ".backup" 指令，或者先把伺服器關閉（停機）再做整包複製。

陷阱 3：還原之後，為什麼前台照片都破圖了？

原因：因為你只還原了資料庫（帳本），卻忘記把 uploads/ 相簿資料夾放回去！
解法：檢查 server/data/uploads/ 裡面有沒有一堆圖片檔案（.png 或 .jpg）。

陷阱 4：備份檔案全部堆在伺服器硬碟，伺服器燒掉一起陪葬

白話忠告：雞蛋不能放在同一個籃子裡！
備份打包好後，建議用 FTP 軟體（例如 FileZilla）或是雲端同步工具，把 .tar.gz 檔案下載一份回到你的筆電或 Google 雲端硬碟。
